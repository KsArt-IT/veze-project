# Lessons learned

Что реально ломалось в прошлых сессиях. Формат: симптом → причина → правило.
Правила, уже записанные в CLAUDE.md, здесь не повторяются — только то, как на них наступили.

## БД (MySQL в Docker)

1. **Кириллица в БД испорчена, а проверка показывала норму.**
   Init-скрипты без `SET NAMES` записали «Україна» как 14 символов мусора. Проверка через тот же
   клиент `mysql` читала с той же ошибкой — двойная порча давала нормальный текст.
   → Проверять кодировку не глазами, а `CHAR_LENGTH(name)` / `HEX(name)`, или читать через
   драйвер приложения (`mysql2`).

2. **Схема была написана на диалекте PostgreSQL, а контейнер — MySQL.**
   `CREATE TYPE ... AS ENUM`, `TIMESTAMPTZ`, `GENERATED ALWAYS AS IDENTITY`, частичные индексы —
   упало бы при первом запуске. README тоже был про `psql` и порт 5432.
   → Перед работой со схемой сверить диалект SQL с образом в `docker-compose.yml`.

3. **Внешний ключ не создаётся: тип колонки не совпал.**
   `buildings.street_id BIGINT` при `streets.id INT` — FK падает.
   → Тип FK-колонки копировать из PK целевой таблицы, включая `UNSIGNED`.

4. **Порядок координат.** В MySQL для SRID 4326 WKT — `POINT(широта долгота)`, а в GeoJSON и
   Leaflet `[lng, lat]` / `[lat, lng]` по-разному.
   → После вставки проверять `ST_Latitude(location)`, а не `ST_AsText`.

5. **`FULLTEXT` не ускоряет автоподсказку.** `name LIKE 'Хре%'` его не использует.
   → Для поиска по префиксу — обычный индекс `(city_id, name)`.

6. **Init упал на длинном `COMMENT`, разбитом на две строки.** `COMMENT 'часть 1 ' 'часть 2'` —
   синтаксическая ошибка 1064, хотя в `SELECT 'a' 'b'` MySQL соседние строки склеивает.
   → `COMMENT` — один литерал; не влезает в 100 символов — сократить текст, а пояснение
   вынести в комментарий `--` над таблицей.

7. **`CHECK` пропустил запрещённую строку из-за `NULL`.** `CHECK (seats > 0 OR cargo_kg > 0)`
   при `seats = 0, cargo_kg = NULL` даёт `NULL`, а `CHECK` с результатом `NULL` считается
   выполненным. → В `CHECK` с nullable-колонкой — `IFNULL(col, 0)` или явный `IS NOT NULL`;
   проверять негативным `INSERT` с `NULL`.

8. **Init упал: `IF(...)` в `CHECK`.** `CHECK (IF(type = 4, amount < 0, amount >= 0))` — ошибка
   3812 «non-boolean type»: результат `IF` для MySQL не логический, даже если обе ветки — сравнения.
   → В `CHECK` только логика: `(type = 4 AND amount < 0) OR (type <> 4 AND amount >= 0)`.

## Docker Compose

9. **Healthcheck говорил `healthy` до выполнения init-скриптов.**
   `mysqladmin ping -h localhost` идёт через сокет, а на время init MySQL поднимает временный
   сервер без сети. → Healthcheck через `-h 127.0.0.1` (TCP).

10. **Сервер терял БД при смене `DB_PORT`.** В контейнер передавался порт хоста, а внутри сети
   compose MySQL всегда на 3306. → Внутри compose порт БД фиксированный, `DB_PORT` — только хост.

11. **Предупреждение `--pid-file` не ушло после переноса в `/var/lib/mysql`.**
   В образе и этот каталог `1777`. → Закрытый `tmpfs` на `/var/run/mysqld` (uid 999, mode 0750).

12. **Не всё в логах MySQL — баги.** `root@localhost is created with an empty password` — штатное
   поведение образа (пароль ставится секундой позже), `CA certificate is self signed` — норма для dev.
   → Не чинить; проверить, что root без пароля получает `Access denied`.

## Процесс

13. **`docker compose down -v` удаляет данные пользователя.**
    → Чистую инициализацию проверять во временном `docker run` с `-v ./init:...`,
    а не пересозданием основного тома.

14. **Init упал, а причину не узнать: контейнер с `--rm` удалился вместе с логами.**
    → Временный контейнер для проверки init запускать без `--rm`, читать `docker logs`,
    потом `docker rm -f`.
